# StockTool v1.1.0 Release Checklist

## Build and promotion

- [ ] Run `build_exe.bat`; verify only `release\staging\StockTool\` changes.
- [ ] Start the staging `StockTool.exe` with an isolated `STOCK_TOOL_USER_DATA_DIR`.
- [ ] Verify `/_stcore/health` returns HTTP 200 with body `ok`.
- [ ] Verify reports, logs, and `data\cache` are writable outside the release directory.
- [ ] Verify 8501, 8502 fallback, and both-ports-busy error logging.
- [ ] Run `publish_release.bat` only after all staging checks pass.
- [ ] Retain the previous release in `release\previous\StockTool` until independent acceptance completes.

## Privacy and user data

- [ ] Record row counts and SHA-256 for `%LOCALAPPDATA%\StockTool\data\portfolio.csv` and `watchlist.csv`.
- [ ] Confirm release contains no `.env`, `secrets.toml`, credentials, portfolio, watchlist, cache, logs, reports, or smoke artifacts.
- [ ] Confirm only `.streamlit\config.toml` is included as Streamlit configuration.

## Manual clean-Windows acceptance

This project has not claimed a clean VM or Windows Sandbox validation unless an independent reviewer completes this checklist.

- [ ] Use a Windows machine or VM without the repository, `.venv`, or a Python installation on `PATH`.
- [ ] Copy only `release\StockTool\` to a temporary directory unrelated to the source tree.
- [ ] Start `StockTool.exe`; verify browser launch or manually open the displayed localhost URL.
- [ ] Verify 8501 primary startup, 8502 fallback, readable error logging when both ports are occupied, and clean shutdown.
- [ ] Verify `%LOCALAPPDATA%\StockTool` is created and remains outside the copied release folder.
- [ ] Verify Windows Defender/SmartScreen prompts, firewall behavior, and write permissions for the current user.

## Rollback

1. Close every `StockTool.exe` process and local listener.
2. Preserve the current `release\StockTool\` folder for investigation.
3. Extract the approved Sprint 5.2.2 rollback archive from `release\baseline\` after checking its `.sha256` sidecar.
4. Restore it as `release\StockTool\` without copying runtime files into it.
5. Recheck the real user-data hashes; rollback must not overwrite `%LOCALAPPDATA%\StockTool`.
