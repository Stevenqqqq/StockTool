## 安裝與資料邊界

- 固定 AppId 不變，安裝於 `%LOCALAPPDATA%\Programs\StockTool`，每位使用者安裝，不要求管理員權限。
- 桌面「股票分析工具」與開始功能表「StockTool」都指向安裝目錄的 `StockTool.exe`，工作目錄亦為安裝目錄。桌面使用既有中文名稱，取代舊 company-depth 預覽捷徑；目前主機捷徑尚未更新。
- 固定啟動器透過 `current-version.json` 選擇 `versions/1.4.3/StockToolPayload.exe`。安裝後會先驗證 payload 版號才切換指向。
- 使用者資料仍在 `%LOCALAPPDATA%\StockTool`。安裝清單及解除安裝清單不包含該資料根目錄；不搬移、不覆寫持股、研究、備份與 Groq 憑證。
- 舊預覽可能使用 `%LOCALAPPDATA%\StockToolPreview\holdings`。本次不自動合併或搬移它，亦不刪除舊預覽資料。若使用者期望預覽中的紀錄出現在正式資料根目錄，須另行核對並授權遷移。
- 靜態邊界檢查不代替實際安裝／解除安裝驗證。先前版本的驗證豁免不適用本次。

## 隔離驗證套件

證據目錄以 `artifact-hash-index.json` 與 `.sha256` 封存；可用 `scripts/verify_artifact_hash_index.py` 核對。候選根目錄的 `delivery-artifacts.json` 另外綁定交接文件、建置／驗證腳本、安裝器與測試套件。Sol 的新驗收輸出應另存其他目錄，不改寫這批已封存證據。`build-payload`、`build-stable` 等目錄是建置中間產物，不是額外交付候選。

`release/v1.4.3-candidate/verify-installation.wsb` 對應 `sandbox-input/`（唯讀）及 `sandbox-output/`（可寫）。網路與剪貼簿關閉，沒有映射真實使用者資料。更換測試主機後，應只修正 WSB 的兩個 HostFolder 絕對路徑，不修改候選或繞過 guest 防護。

測試資料由既有離線測試 fixture 新建：合成持股 CSV、有效研究工作階段與有效備份；未複製真實紀錄。Groq 憑證由 guest 自行建立假的 DPAPI 加密字串，不讀取或外送真實金鑰。

有 Windows Sandbox 時開啟 WSB；其他全新可丟棄 Windows VM，將 `sandbox-input` 複製到 `C:\StockToolInput`，於 guest 執行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\StockToolInput\verify_v143_sandbox.ps1
```

Sol 如需在解除安裝前親自檢視畫面，於上列命令加 `-ReviewBeforeUninstall`；腳本會在已完成兩次啟動後暫停，供 reviewer 從 guest 桌面開啟產品、另存畫面證據，輸入 `CONTINUE` 後才停止產品並測解除安裝。此互動模式仍只可在全新 guest 執行，不能在主機使用。

腳本依序安裝 1.4.2、置入合成資料與舊預覽捷徑、升級 1.4.3、核對全部 installed payload 檔案、核對兩個捷徑、從桌面啟動及開始功能表重啟，最後解除安裝。每階段檢查既有合成檔案雜湊及假 DPAPI 仍可讀；正常新增的日誌／快取不冒充既有資料零變更。解除安裝後確認程式、版本目錄、捷徑及解除安裝登錄項消失，合成資料仍完整。

結果輸出 `lifecycle-result.json` 與 Inno 日誌。健康端點及 payload 程序核對不代表可見 UI 已驗收，因此腳本保留 `ui_content_verified: false`。Sol 應另在 guest 開啟畫面，確認版本、合成持股、保存研究及重啟可讀。未出現真實 guest 的完整 passed 紀錄前，本文件的阻擋狀態不得改為通過。
